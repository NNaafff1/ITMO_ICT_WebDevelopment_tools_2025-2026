# Итоговые выводы

## Сравнительная таблица обеих задач

| Задача | Тип нагрузки | threading | multiprocessing | async |
|---|---|---:|---:|---:|
| Задача 1 (сумма 1..10⁸) | CPU-bound | 3.64 сек | **1.73 сек** ⭐ | 3.93 сек |
| Задача 2 (парсинг 12 URL) | I/O-bound | 6.55 сек | 4.24 сек | **0.88 сек** ⭐ |

⭐ — лучший подход для данной задачи.

## Ключевые выводы

1. **GIL** в CPython делает потоки бесполезными для CPU-bound задач,
   но не мешает для I/O.

2. **Multiprocessing** — единственный честный способ параллельных
   вычислений в Python, но он дорогой по ресурсам.

3. **Asyncio** даёт максимальную эффективность для массовых
   I/O-операций при минимальном расходе памяти (один процесс,
   один поток, тысячи корутин).

4. **Выбор инструмента диктуется характером нагрузки**:
    - **CPU-bound** → `multiprocessing`
    - **I/O-bound малый** → `threading`
    - **I/O-bound массовый** → `asyncio`

5. **Асинхронное взаимодействие с БД** через `psycopg` отлично
   сочетается со всеми тремя подходами и не блокирует event loop /
   поток-владелец.

## Картинка, которую стоит запомнить

```
                  ┌──────────────┐
   Задача         │ Что выбрать? │
                  └──────────────┘
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   CPU-bound       I/O-bound        I/O-bound
   (вычисления)    (малый)          (массовый)
        │                │                │
        ▼                ▼                ▼
 multiprocessing    threading         asyncio
```
