# Теоретические основы

## GIL — Global Interpreter Lock

В CPython одновременно выполняется только один поток Python-кода —
такова работа GIL (Global Interpreter Lock). Это означает, что несколько
потоков **не дают реального параллелизма** для задач, нагружающих
процессор: они лишь переключаются по очереди. Для I/O-операций GIL
отпускается на время ожидания, поэтому потоки полезны для сетевой
работы, файлов и т.п.

## Threading

Модуль `threading` создаёт потоки внутри одного процесса. Потоки делят
память, легковесны, переключение между ними дешёвое.

**Подходит для:** I/O-bound задач (сеть, диск, ожидание).

**Не подходит для:** CPU-bound вычислений — из-за GIL.

## Multiprocessing

Модуль `multiprocessing` запускает отдельные процессы. У каждого свой
интерпретатор и своя память, GIL на них не действует.

**Подходит для:** CPU-bound задач — реальное ускорение пропорционально
числу ядер процессора.

**Минусы:** большой overhead на запуск процессов и сериализацию данных
между ними.

## Asyncio

`asyncio` работает в одном потоке через цикл событий (event loop) и
кооперативную многозадачность: корутины добровольно отдают управление
при `await`.

**Подходит для:** массовых I/O-операций (сотни/тысячи параллельных
запросов).

**Не подходит для:** CPU-bound без `asyncio.to_thread` или
`run_in_executor`.

## Когда что использовать

| Тип нагрузки | Threading | Multiprocessing | Asyncio |
|---|:---:|:---:|:---:|
| CPU-bound | ✗ (GIL) | ✓ **лучший** | ✗ |
| I/O-bound (малый объём) | ✓ | ✗ overhead | ✓ |
| I/O-bound (массовый, сотни запросов) | средне | ✗ | ✓ **лучший** |
